Sarvanetra AI · Gujarat Police

How Sarvanetra is built

A traffic-intelligence platform over 30 live CCTV cameras in Junagadh district. Two processes, one database: a GPU ingestion pipeline that turns frames into tracks, plates, speeds and alerts, and an API that serves a React control room. This page is the reference for explaining any part of it.

01 From a frame to an alert

The single path everything else hangs off. One camera frame enters at the top; what leaves at the bottom is a row an officer can act on.

1

Read the frame

One reader thread per camera pulls from the camera's HLS stream, or from harvested local clips when the stream is unavailable. Sampling is throttled to a target rate so the GPU is never the thing that falls behind.

CameraReaderThread · live_24x7_pipeline.py
2

Detect and track vehicles

YOLOv8s at 1280 px finds vehicles, people and two-wheelers. BoT-SORT assigns a track id that survives across frames, and its global motion compensation separates camera shake from vehicle movement.

BoTSORTTracker · services/tracker.py
3

Place the vehicle on the ground

The bottom-centre of the box is the contact point with the road. On a calibrated camera a homography maps that pixel to metres. Points too close to the vanishing line are dropped: one pixel of jitter there is worth hundreds of metres.

pixel_to_world_m, pixel_world_resolution_m · services/calibration.py
4

Read the plate

A second YOLO model finds the plate inside the vehicle crop. Three CRNN networks with CTC decoding read it at 64×256 and vote; Indian plate grammar resolves the state code and rejects impossible strings. A temporal voter combines readings across the track.

ANPREngine · services/anpr_engine.py
5

Measure the speed

When the track ends, a Theil–Sen regression over its world-plane positions gives a speed robust to outliers, with a bootstrap confidence interval. Gates reject anything physically impossible, and pedestrians never receive a traffic speed.

estimate_track_speed · services/speed_estimator.py
6

Match, decide, alert

The plate is checked against the watchlist with one-character tolerance. Congestion is compared against the camera's own learned baseline. A clone check asks whether the same registration has appeared somewhere it could not have reached in time.

watchlist_service, traffic_baseline, plate_clone_detector
7

Persist and publish

Tracks, plates and alerts are written to SQLite. The annotated frame is published to disk atomically for the API process, which serves it to the control room; alerts also go out over WebSocket so the feed updates without polling.

output/live_frames/ · ws/dashboard_ws.py

Why two processes. Ingestion decodes and infers continuously; the API must answer short requests while it does. Measured on this machine with both in one process, the calibration page and /docs both timed out after 30 s while it held 6.7 GB and 1,067 s of CPU. They now share only the database and a frame directory.

02 Backend

FastAPI and SQLAlchemy over SQLite in WAL mode, PyTorch and Ultralytics for inference, OpenCV for everything frame-shaped. 439 Python modules; the ones below carry the weight.

Cross-cutting concerns

  • Auth — HS256 JWT, three roles (admin, operator, viewer). Camera visibility is scoped by department, so an operator sees only their own cameras.
  • Audit — every alert view and plate search is logged with the user and IP; 4,198 entries so far.
  • Evidence — SHA-256 over the clip, a chain-of-custody PDF, and an honest failure when no footage exists.
  • Fleet census — one predicate decides what counts as a camera, so test rigs and deleted rows cannot leak into a count.
  • Provenance — seeded rows are excluded from search by a structural test, not a date cut.
  • Heartbeat — camera liveness polling with a failure threshold, separate from stream health.

03 The five neural models

Each was chosen for a job the others cannot do, and each ships as a trained checkpoint in the repository.

ModelArchitectureJobInput
Vehicle detectorYOLOv8sCars, trucks, buses, two-wheelers, people1280 px frame
Plate detectorYOLOv8, plate_v3_ftTight plate box inside a vehicle crop320 px crop
Plate reader3× CRNN + CTCReads the characters; the three vote64×256 grey
Vehicle / person ReIDOSNet-IBN, fine-tuned512-d embedding for cross-camera matchingcrop → FAISS
FaceInsightFace buffalo_l512-d face embedding for the watchlistface crop

The plate detector runs on the vehicle crop, not the frame. A common critique is that imgsz=320 shrinks a 70 px plate to 17 px. Measured on 370 real crops, the median vehicle crop is 129 px wide and only 5% exceed 320 — so for most vehicles 320 is a 2.5× upscale. Raising it to 640 or 960 finds fewer plates: −7% and −11%.

06 Frontend

React 19 on Vite, no UI framework — the styling is hand-written CSS with design tokens, so the control room can be themed to whatever a department already uses.

Libraries, and why

  • react-leaflet — the GIS map: camera nodes, corridors, anomaly markers
  • hls.js — plays the camera HLS streams the browser will not decode natively
  • TanStack Query — server state, caching and refetch for the feeds
  • TanStack Virtual — keeps the alert feed fast when it holds thousands of rows
  • react-resizable-panels — the operator lays out their own control room
  • focus-trap-react — modals stay keyboard-navigable

How data arrives

  • WebSocket for alerts, so the feed updates the moment one is raised
  • Polled snapshots for camera views — one authenticated JPEG every 800 ms, fetched as a blob because an <img> cannot carry a bearer token
  • REST for everything else, department-scoped by the same token

09 What does not work, and why

Every system has these. Naming them with numbers is what separates a measured system from a demonstrated one.

Speed is reported on one camera, not thirty by design

A speed needs a homography, and a homography needs either a survey or road markings. CAM_08 and CAM_11 were calibrated by a vanishing-point method that cannot work at a junction: their own robust refit records “only 20% of lines agree” and “track directions span 113°”. Measured against IRC zebra spacing, the result overstated ground distance by about 3× — a vehicle at 30 km/h would have been reported at 89. Both calibrations are deactivated; those cameras now report no speed, which is the truthful answer.

The active calibration's scale is provisional labelled

On CAM_09 the geometry is measured — 26 equally spaced road markings, straight to 1.19 px, their spacing integer-consistent to within 0.19. The lateral scale is measured too: 57 car widths give 1.83 m against a true 1.80. The longitudinal metre is not: it is set from a traffic prior, so the database records calibration_method="provisional_traffic_prior" and speed_validated=false. Ratios between vehicles are sound now; the absolute level moves the moment one distance is measured on the ground.

Fleet-wide ANPR is 0.3% per track optics

Not a model failure. The median plate this fleet presents is 58 px wide and only 3.7% reach 100 px, against a 70 px floor below which the recogniser is right almost never. Seven approaches were measured and rejected, including logit fusion, self-training on 2,271 unlabelled vehicles, and night enhancement — which made accuracy worse, 42.2% to 18.1%, because the recogniser had never seen enhanced images. More real labelled plates is the only lever left.

Camera health is a single shared heartbeat known

All 30 cameras share one timestamp, so status=ONLINE carries no per-camera information. The fleet map must never be presented as live health.

Say this out loud in the demo. A panel of traffic engineers knows no system is perfect. A team that can state its limits in numbers — and show the guard rails that stop a bad number reaching an officer — is a team that has measured its own work.

10 Running it

Two processes, started separately

API + control room
  python scripts/run_server.py            # :8000, no --reload
  cd frontend && npm run dev              # :5173

Ingestion, focused on one camera
  SENTINEL_ONLY_CAMERAS=CAM_09     # give one camera the whole GPU
  SENTINEL_CLIP_MATCH=0830         # pick the clip, not the 1 a.m. empty road
  SENTINEL_FORCE_CLIPS=1           # ignore a stream that is merely crawling
  SENTINEL_READER_FPS=5            # more frames per vehicle
  python -m backend.scripts.run_pipeline

Before demonstrating

python -m backend.scripts.warm_voice_alerts --limit 20   # speech, offline-safe
python -m backend.scripts.test_plate_clone_detector      # 10/10 in front of judges
python -m backend.scripts.detect_plate_clones --stage-demo

Keep 20–30 GB of disk free. With the drive full, the pipeline wrote a 0-byte frame, the API served it as a JPEG, and the live camera view rendered black — looking exactly like a dead camera. Both sides now guard against it, but SQLite writes and even source edits fail on a full disk.

Sign in

Use admin for a demonstration: camera visibility is department-scoped, so operator sees 2 cameras and viewer sees 11. That scoping is worth showing deliberately — it is a security feature — but not by walking into it.
